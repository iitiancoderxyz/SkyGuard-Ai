## 1. Evidence Rendering Problem

During UI verification of the Evidence section within anomaly analysis cards, raw HTML markup strings with inline CSS styling (e.g. `<span style="...">`, `<div>`, class names, or escaped HTML tags) were identified. When Streamlit rendered these strings or when unexpected characters were present, raw markup tags became visible to operational meteorologists, degrading readability and creating an unprofessional interface.

---

## 2. Evidence Rendering Fix

1. **Replaced HTML Injection with Native Markdown:**
   In `dashboard/components/explainability.py`, the `render_evidence_chips()` function was updated to eliminate raw `<div>` and `<span>` HTML tags. It now renders clean, native Streamlit markdown bullets using standard formatting (`• 🌦️/⚠️/📡/🔍 **Title**: Explanation`).
2. **Standardized Human-Readable Mapping:**
   Added a complete dictionary lookup mapping internal rule codes and ML evidence tags to plain English descriptions with clear meteorological context (e.g., thermodynamic consistency, gradient checks, telemetry integrity, rate of change limits).
3. **Graceful Fallback:**
   For any raw token or unmapped string, formatted readable fallback text is generated by replacing underscores and capitalizing terms without emitting unparsed HTML tags.

---

## 3. Human-Readable Evidence Examples

Below are representative examples of how evidence is now formatted for operators:

- **Weather Event Agreement:** `• 🌦️ Genuine meteorological weather event detected; physical gradients verified across surrounding parameters.`
- **Thermodynamic Consistency:** `• 🌦️ Thermodynamic consistency verified between relative humidity, temperature, and dew point.`
- **Spatial Consistency:** `• 🌦️ Spatial consistency confirmed with adjacent regional weather stations.`
- **Sensor Spike / Step Jump:** `• ⚠️ Sudden unphysical jump or spike detected exceeding realistic meteorological rate-of-change limits.`
- **Sensor Flatline / Frozen State:** `• ⚠️ Sensor values remained perfectly static over an extended observation window, indicating hardware flatline.`
- **Calibration Drift:** `• ⚠️ Gradual calibration drift detected relative to physical and spatial baseline expectations.`
- **Telemetry / Communication Gap:** `• 📡 Telemetry transmission gap or delayed data packet arrival detected.`
- **Duplicate Observation:** `• 📡 Duplicate timestamp received with conflicting sensor values.`
